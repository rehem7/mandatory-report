# UI v1 · Wise-inspired

Reference: https://github.com/VoltAgent/awesome-design-md/blob/main/design-md/wise/DESIGN.md

This is an adaptation for the mandatory-report demo, using the reference's lime accent, sage canvas, dark ink, rounded surfaces and clear typographic hierarchy.

## Tokens

- Primary action: `#9fe870`; hover: `#b5f28e`.
- Canvas: `#e8ebe6`; cards: white; secondary surface: `#f5f7f2`.
- Heading/action ink: `#163300`; body: `#51594c`.
- Card radius: 24px; input radius: 12px; buttons: pills.
- Chinese text uses installed system fonts; no proprietary font assets are bundled.

## Page structure

- Login: a light sage canvas with an injured child on the left, a white authentication card in the center, and a smiling child on the right. Transparent portraits face inward; on phones, both portraits sit above the card, and on very short phone screens they yield space to the form. Adapt spacing and card height to the viewport so the complete page fits common laptop and phone screens. Login and registration share the same height and submit position; registration uses two compact rows even when the other-identity field is visible. Email registration collects an immutable reporting identity. The receiver entry appears only on this page.
- Login motion: one finite fade-and-rise entrance; a sliding login/register selection indicator; a left-to-right underline on field focus; a small submit-arrow hover movement. Keep motion compositor-friendly and honor reduced-motion preferences. Use native CSS to retain the lightweight runtime.
- Auth submit highlight: use the React Bits Specular Button WebGL shader and rounded-rim geometry through a native lifecycle adapter. Keep the green 44px button and add proximity-based rim light, pointer following and a short press flash. Keyboard focus raises the highlight; reduced motion holds it stationary; disabled/hidden/idle states stop rendering. If WebGL is unavailable, preserve the static working button. Update only the text label during requests so the canvas and arrow survive errors and retries.
- Login title: React Bits Stroke Text adapted as native SVG/WAAPI. Retain demo timing: draw 1.6s, fill delay 0.2s, per-character stagger 0.05s, outline 1.4, solid stroke, left wipe, mount playback and pointer hover outline redraw. Sage outline and dark-green fill match the page. The complete sentence shares one SVG with optical comma spacing, a slightly larger responsive size and one normalized path per actual glyph contour; complex Chinese letters must draw every inner component. Fixed vector title artwork is generated by `scripts/build-login-title.py` from the locally installed bold font; font files are not served. Invisible HTML text reserves layout and remains the no-script fallback. Reduced motion displays the completed text immediately. Source and license are linked at `/credits`.
- Login art cards: a compact React Bits Bounce Cards fan fills the desktop space above the smiling child, using five Storyset Rafiki scenes: parents with a child, teacher with a pupil, children reading, pediatric care, and children playing. Use local SVGs, a 0.5s entrance delay, 0.06s stagger and spring bounciness 0.6; hovering lifts the selected card and gently spreads its neighbours. Match the free space at each desktop size; hide this decorative fan below 1200px width or 700px height to preserve the one-screen form. Load its illustrations only when visible. The spring loop sleeps when idle/hidden, and reduced motion shows the final fan immediately. Remove the caption below the fan and keep the visible Storyset credit in the page footer. Raise the fan roughly 24px in the annotated 1651x764 layout; compact laptop sizes keep enough clearance from the guest entry and portrait.
- Public service: left navigation for questions, training, learning, reporting, records and personal training ledgers, with the current account identity and logout action. Guests can access every public feature.
- Sidebar profile: a compact two-line name/identity block with login or logout on the right (47px desktop, 40px phone). Use five local adult head-and-shoulder crops from Storyset Group / Rafiki, with source details in `public/assets/visual/avatar-sources.json` and credit at `/credits`. Derive the portrait index from the existing random owner ID so navigation and reloads keep it stable; account owners keep it across browsers, and logout restores the original guest portrait. Guest identity uses the existing HttpOnly visitor Cookie and server session (14 days), never an IP address. Truncate long names visually and expose the complete value in the title.
- Public navigation icons: adapt React Bits Glass Icons into small CSS layers: a coloured tilted plate, a frosted translucent face, edge highlights and a white Lucide glyph. Six distinct tones identify the service areas: ask blue, training purple, learning orange, report teal, records pink, ledger green. The complete nav link retains its text, active state, keyboard focus and route semantics; decorative layers are aria-hidden. Keep the mobile horizontal navigation compact and preserve breadcrumb labels independently of the nested icon markup.
- Public navigation: questions, training, learning, records and ledgers share one document. Keep up to eight live page fragments in memory for the current owner, including unsent inputs and scroll position; refresh changing records in the background. Report navigation retains its draft-save/attachment-flush guard. Account departure clears page fragments; identity changes rebuild the page.
- Loading: account, catalog and sanitized AI configuration arrive in one private, uncached bootstrap response. Preload shared modules. Public HTML revalidates with ETags; versioned modules/styles/assets use immutable caching and compressed responses. Restart the local server after source edits to publish a new asset revision. Personal API responses stay `no-store`.
- Report: a three-section form, locked registered identity, a link to AI conversation, account draft synchronization and receipt history; guests retain local drafts.
- Receiver: department sidebar, four summary metrics, searchable queue, distributions, collapsible audit log, and a native case detail dialog.
- Red means risk/overdue/error. Anonymous reports use neutral styling.
- Responsive layout: stacked public form and assistant on phones, horizontal department navigation, and horizontally scrollable data tables.
- Real AI serves public conversations, training characters and feedback. Receiver assessment remains a rule demonstration with human confirmation.
- AI progress: before the first token, show a native disclosure with real model request and tool events. Update live through SSE and restore from the owner's active generation after reload. Completed answers and training feedback retain a collapsed operation record. Only fixed status text and source counts are public: never include model reasoning, prompts, tool arguments or provider credentials. Mark failures, tool compatibility fallback and search fallback accurately; stopping clears the unfinished reply and restores its input. Respect reduced motion.
- Chat geometry: the welcome, waiting, responding and stopped states share the same viewport-based card height. Let the message area scroll internally; do not change the outer height based on the presence of welcome artwork.
- Training forms persist through the backend; simulated reports never enter the police queue. Personal training exports contain completion and scoring summaries.
- Training feedback: send the coach a Chinese presentation of selected option labels, filled or missing text, checkbox states, and fixed scores. Never send the raw worksheet schema or enum values as instructional context. Explain selections naturally in Chinese and distinguish a checked box from an action actually completed.
- AI text: render both streaming and saved content with the local markdown-it 15.0.3 + markdown-it-cjk-friendly 3.0.0 bundle (`public/vendor/markdown-it.js`). Support emphasis next to Chinese punctuation, nested lists, headings, code and separators; keep raw HTML disabled, reject unsafe link schemes, and show image descriptions without fetching external media. Retain third-party notices at `/credits`. Completed historical feedback receives the same Markdown rendering; prompt wording applies to newly generated feedback.

## Iterate

Adjust shared colors, spacing, font sizes and radii in `public/style.css`. Keep public reporting and internal processing visually consistent. Check desktop and phone layouts after structural changes.

## Material direction

Children must be visible protagonists in themed illustrations; matching color alone is insufficient. Use scenes with a young child receiving adult support, a primary-school pupil with a teacher, and children reading together. Do not substitute adult therapy, generic office/security graphics, or university-aged students. Retain the sage palette, but choose by subject, age and interaction first. Keep clear space around working forms and records.

Integrated assets: Storyset Rafiki Parents, Teacher student, and Kids reading; visible attribution in illustrated pages and details at `/credits`. Sources and original hashes are retained in `public/assets/visual/illustration-sources.json`. Twenty Lucide icons form the shared SVG system in `public/icons.js`; retained notices cover ISC/MIT. React Bits Fade Content and Spotlight Card interaction references are adapted in native `visual.js`, with a finite intersection-triggered reveal and a low-intensity pointer-following glow. Respect reduced motion, avoid permanent render loops, and keep assets local, versioned and compressed. The original guardian-sprout brand mark is shared across login, public pages and the receiver workbench.
